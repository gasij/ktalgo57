# Путеводитель по коду: классы и переменные

## Главное, что нужно не перепутать: три вида индексов

В коде одновременно живут три нумерации. Почти все вопросы «а что тут +1?» — про них.

| Индекс | Что нумерует | Диапазон | Где используется |
|---|---|---|---|
| **node** (вершина) | Перекрёсток города | 0 … V−1 | `RoadNetwork`, Дейкстра |
| **point** (ключевая точка) | Склад и адреса заказов | 0 = склад, 1 … k = заказы | `TravelTimes.Minutes(from, to)` |
| **order** (заказ) | Заказ в списке `problem.Orders` | 0 … k−1 | DP, жадный, маски |

Связь между ними: **заказ `i` — это точка `i + 1`**, склад — точка `0`. Отсюда все `i + 1` и `next + 1` в коде. Точка превращается в перекрёсток через массив `_nodeOfPoint` в `TravelTimes`.

---

## Как классы работают вместе

```
JSON-файл ──ScenarioLoader──► DeliveryProblem (RoadNetwork + Orders + склад + смена)
                                     │
                              TravelTimes  ← запускает ShortestPaths.Dijkstra из каждой точки
                                     │       (матрица времён между точками)
                    ┌────────────────┴────────────────┐
             DpRoutePlanner                    GreedyRoutePlanner
          (находит порядок заказов)          (находит порядок заказов)
                    └────────────────┬────────────────┘
                               RouteBuilder  ← проверяет порядок и собирает план
                                     │
                                 RoutePlan  ──ConsoleReport──► консоль
```

## Библиотека `src/CourierRouting/`

### Graph/RoadNetwork.cs — дорожная сеть

**`Road`** — одна дорога (дуга графа).
- `To` — номер перекрёстка, куда ведёт дорога.
- `Minutes` — время проезда.

**`RoadNetwork`** — граф города, **список смежности**.

| Член | Что это |
|---|---|
| `_adjacency` | Список смежности: `_adjacency[v]` — все дороги, выходящие из перекрёстка `v` |
| `_names` | Имя перекрёстка по номеру: `_names[3]` = «Вокзал» |
| `_indexByName` | Обратный словарь: номер по имени |
| `NodeCount` | V — число перекрёстков |
| `RoadCount` | E — число дуг (двусторонняя дорога = 2 дуги) |
| `AddNode(name)` | Добавить перекрёсток или вернуть номер уже существующего |
| `AddRoad(from, to, minutes, twoWay)` | Добавить дорогу; при `twoWay = true` — обе дуги. **Здесь отклоняется отрицательное время** |
| `RoadsFrom(v)` | Дороги из `v` — то, что перебирает Дейкстра |
| `Name(v)` / `IndexOf(name)` | Перевод номер ↔ имя |

### Graph/ShortestPaths.cs — Дейкстра

**`ShortestPaths.Dijkstra(network, source)`** — алгоритм Дейкстры от одного перекрёстка.

| Переменная | Что это |
|---|---|
| `n` | Число перекрёстков |
| `distance[v]` | Лучшее известное время от `source` до `v`; в начале — `Unreachable` (= int.MaxValue) |
| `previous[v]` | Из какого перекрёстка пришли в `v` по кратчайшему пути; −1 — у источника и недостижимых |
| `heap` | Очередь с приоритетом: (перекрёсток, расстояние), всегда достаёт ближайший |
| `node`, `dist` | Извлечённый из кучи перекрёсток и расстояние, с которым его положили |
| `dist > distance[node]` | Устаревшая запись — пропускаем («ленивое удаление») |
| `candidate` | Время до соседа через `node`; в `long`, чтобы не было переполнения |

**`ShortestPathTree`** — результат Дейкстры.
- `DistanceTo(v)` — кратчайшее время до `v`.
- `CanReach(v)` — достижим ли `v`.
- `PathTo(v)` — сам путь: идёт по `previous` от `v` назад к источнику, потом разворачивает список.

### Model/ — данные задачи

**`Order`** — заказ.

| Поле | Что это |
|---|---|
| `Id` | Номер заказа («A», «F1») |
| `Location` | Имя перекрёстка-адреса |
| `Value` | Ценность — что максимизируем (≥ 1) |
| `DeadlineMinute` | Крайняя минута прибытия; `null` — без дедлайна |
| `ServiceMinutes` | Сколько минут занимает передача заказа |

**`DeliveryProblem`** — вся постановка.
- `Network` — город.
- `Depot` — имя склада.
- `Orders` — заказы.
- `ShiftMinutes` — T, длина смены.

**В конструкторе проверяются все входные данные**: неизвестный адрес, повтор `Id`, отрицательные значения, ценность ≤ 0.

**`RoutePlan`** — результат.

| Член | Что это |
|---|---|
| `Stops` | Список остановок `Stop(Order, ArrivalMinute, DepartureMinute)` — время прибытия и отъезда |
| `Skipped` | Недоставленные заказы `SkippedOrder(Order, Reason)` |
| `StreetPath` | Полный путь по перекрёсткам: склад → … → склад |
| `ReturnMinute` | Минута возвращения на склад |
| `TotalValue` | Сумма ценностей доставленных заказов |

**`SkipReason`** — почему заказ не доставлен.
- `Unreachable` — нет пути туда или обратно.
- `DeadlineUnreachable` — не успеть даже напрямую.
- `ShiftTooShort` — даже один этот заказ не укладывается в смену.
- `NotSelected` — сам по себе выполним, но не поместился в маршрут.

### Planning/TravelTimes.cs — сжатие графа (шаг 1)

Превращает город из V перекрёстков в матрицу (k+1)×(k+1) между ключевыми точками.

| Член | Что это |
|---|---|
| `_nodeOfPoint[p]` | Номер перекрёстка для точки `p` (0 — склад, i+1 — адрес заказа i) |
| `_treeOfPoint[p]` | Дерево кратчайших путей Дейкстры **из** точки `p` |
| `treeByNode` | Кэш: если у двух точек один перекрёсток, Дейкстра запускается один раз |
| `PointCount` | k + 1 |
| `DijkstraRuns` | Сколько раз реально запускалась Дейкстра |
| `Minutes(from, to)` | **Главный метод:** кратчайшее время между точками |
| `Path(from, to)` | Путь по перекрёсткам между точками (для `StreetPath`) |

### Planning/DpRoutePlanner.cs — DP по подмножествам (шаг 2, главный файл)

**Константы.**

| Константа | Что это |
|---|---|
| `MaxOrders = 20` | Максимум заказов: дальше таблица не помещается в память |
| `NotReached = int.MaxValue` | В `finish`: состояние не достигнуто |
| `FromDepot = −1` | В `previous`: заказ был первым, перед ним — склад |

**Подготовка.**

| Переменная | Что это |
|---|---|
| `k` | Число заказов |
| `deadline[i]` | Дедлайн заказа `i`; без дедлайна — `long.MaxValue` (ограничения нет) |
| `service[i]` | Время передачи заказа `i` |
| `back[i]` | Кратчайшее время от заказа `i` до склада |
| `shift` | Длина смены T |
| `states` | Размер таблицы: 2^k · k |

**Таблица DP.**

| Переменная | Что это |
|---|---|
| `mask` | **Битовая маска доставленных заказов.** Бит `i` = 1 → заказ `i` доставлен. Пример при k = 3: `101₂ = 5` → доставлены заказы 0 и 2 |
| `last` | Заказ, доставленный последним — у него сейчас стоит курьер |
| `next` | Заказ, который пробуем доставить следующим |
| `finish[mask * k + last]` | **Значение DP:** самая ранняя минута, когда курьер закончил заказ `last`, доставив ровно `mask`. Таблица двумерная `[mask][last]`, но хранится одномерным массивом: индекс = `mask * k + last` |
| `previous[mask * k + last]` | Какой заказ был перед `last` в лучшем маршруте; `FromDepot` — если `last` первый. Тип `sbyte` (1 байт) для экономии памяти |

**Функция `Relax` — один переход DP.**

| Переменная | Что это |
|---|---|
| `fromPoint` | Откуда едем — номер **точки** (0 — склад, иначе `last + 1`) |
| `fromOrder` | Откуда едем — номер **заказа** (для `previous`); `FromDepot` со склада |
| `time` | Во сколько освободились на предыдущем месте |
| `leg` | Время проезда до `next` |
| `arrival` | Время прибытия к `next`; проверяется дедлайн `arrival > deadline[next]` |
| `done` | Время окончания передачи: `arrival + service[next]` |
| `done + back[next] > shift` | **Отсечение:** со склада уже не успеть — состояние не сохраняется |
| `mask \| (1 << next)` | Новая маска: к доставленным добавили `next` |
| `index` | Ячейка нового состояния `(mask ∪ {next}, next)` |
| `done < finish[index]` | Нашли более ранний путь в это состояние → запоминаем |

**Выбор ответа.**

| Переменная | Что это |
|---|---|
| `valueOfMask[mask]` | Суммарная ценность заказов в маске. Считается через маску без младшего бита: `valueOfMask[mask & (mask − 1)] + ценность младшего заказа` |
| `low` | Номер младшего установленного бита маски (`TrailingZeroCount`) |
| `t` | `finish` текущего состояния |
| `returnMinute` | Когда курьер вернётся на склад из этого состояния: `t + back[last]` |
| `bestValue`, `bestReturn` | Лучшая ценность и время возврата при ней; в начале — 0 и 0, это пустой маршрут |
| `bestMask`, `bestLast` | Состояние, где достигнут лучший результат; `bestLast = −1` — пустой маршрут |

**Восстановление пути.**
- `sequence` — порядок заказов, собирается с конца.
- `prev` — предыдущий заказ.
- `mask &= ~(1 << last)` — снять бит заказа `last`.
- В конце `sequence.Reverse()` переворачивает порядок.

### Planning/GreedyRoutePlanner.cs — жадный «ближайший сосед»

| Переменная | Что это |
|---|---|
| `done[i]` | Заказ `i` уже доставлен |
| `sequence` | Порядок выбранных заказов |
| `time` | Текущая минута |
| `point` | Текущая точка (0 — склад) |
| `best` | Номер ближайшего выполнимого заказа на этом шаге; −1 — таких нет, конец |
| `bestLeg` | Время езды до него |
| `leg`, `back`, `arrival` | Как в DP: до заказа, от заказа до склада, время прибытия |

### Planning/RouteBuilder.cs — проверка и сборка плана

`TryBuild(problem, travel, sequence)` — по готовому порядку заказов пересчитывает время, проверяет дедлайны и смену и возвращает `RoutePlan` (или `null`, если порядок недопустим). Его используют **оба** планировщика.

| Переменная | Что это |
|---|---|
| `orderIndex` | Номер заказа из `sequence` |
| `next` | Его точка: `orderIndex + 1` |
| `point` | Где курьер сейчас (номер точки) |
| `time` | Текущая минута |
| `stops` | Накопленные остановки |
| `back` | Время возврата на склад из последней точки |

Вспомогательные методы:
- `BuildStreetPath` — склеивает пути между точками в один путь по перекрёсткам. `points` — точки по порядку, `nodes` — перекрёстки. `Skip(1)` убирает повтор стыковочного перекрёстка.
- `ClassifySkipped` — определяет `SkipReason` для недоставленных заказов. `selected` — множество выбранных, `there` и `back` — время туда и обратно со склада.

### Planning/IRoutePlanner.cs

Общий интерфейс планировщиков: `Name` и `Plan(problem, travel)`. Благодаря ему DP и жадный взаимозаменяемы.

### Io/ScenarioLoader.cs

Читает JSON в `DeliveryProblem`. `ScenarioDto`, `RoadDto` и `OrderDto` — промежуточные классы, точно повторяющие структуру JSON. Битый JSON превращается в `FormatException`.

## Пример: как DP проходит ловушку `02-greedy-trap`

Заказы: 0 = N (Киоск), 1 = F1 (Офис 1), 2 = F2 (Офис 2). Смена 75. Время со склада: N — 5, F1 — 30, F2 — 35.

| Маска (биты 2-1-0) | last | finish | Как получено |
|---|---|---|---|
| 001 {N} | N | 5 | склад → N |
| 010 {F1} | F1 | 30 | склад → F1 |
| 100 {F2} | F2 | 35 | склад → F2 |
| 011 {N, F1} | F1 | 40 | N(5) + 35; возврат 40 + 30 = 70 ≤ 75 ✓ |
| 011 {N, F1} | N | 65 | F1(30) + 35; возврат 65 + 5 = 70 ✓ |
| 101 {N, F2} | — | — | N(5) + 40 = 45, возврат 80 > 75; F2(35) + 40 = 75, возврат 80 — оба отсечены |
| 110 {F1, F2} | F2 | 35 | F1(30) + 5; возврат 35 + 35 = 70 ✓ |
| 110 {F1, F2} | F1 | 40 | F2(35) + 5; возврат 40 + 30 = 70 ✓ |
| 111 {все} | — | — | любой порядок даёт возврат > 75 — отсечено |

Ценность: маски 011 → 6, маски 110 → **10**. Ответ — {F1, F2}, возврат в 70.
