Выбор заказов и порядка их доставки при ограничении смены и дедлайнах: алгоритм Дейкстры + динамическое программирование по подмножествам

Продолжение задачи КТ7 «Маршрут дрона с ограниченным зарядом»
Задача

Больше ценных заказов — и назад до конца смены

Вход

  • Дорожная сеть — ориентированный граф, вес дуги — минуты проезда (≥ 0), есть односторонние улицы
  • Склад и смена T минут
  • Заказы: адрес, ценность, дедлайн (необязательный), время передачи

Выход

  • Какие заказы везти и в каком порядке, время прибытия, путь по улицам
  • Недоставленные заказы — с причиной

Критерий

Максимум суммарной ценности; при равенстве — более раннее возвращение.

Ограничения

Прибытие к заказу ≤ его дедлайна
Возврат на склад ≤ T

Нужно решить сразу две задачи: выбрать подмножество заказов (как в рюкзаке) и порядок объезда (как в задаче коммивояжёра). Задача NP-трудная.

Шаг 1 · Графы

Дейкстра из k + 1 точек по списку смежности

  • Ключевые точки — склад и адреса заказов; одинаковые адреса считаются один раз
  • Куча PriorityQueue без decrease-key: устаревшие записи пропускаются при извлечении, записей ≤ E + 1
  • Для каждой точки хранится дерево предшественников — по нему восстанавливается путь по улицам
  • Отрицательное время проезда отвергается при вводе: на нём Дейкстра некорректна

отклонено

Шаг 2 · Динамическое программирование

Состояние — какие заказы доставлены и где курьер

finish[mask, last] — самая ранняя минута, когда курьер закончил заказ last, доставив ровно множество mask, не нарушив дедлайнов и ещё успевая на склад

  • База: finish[{j}, j] = dist(склад, j) + service(j)
  • Порядок: маски по возрастанию — переход только добавляет бит
  • Ответ: max value(mask) по всем достигнутым состояниям; пустой маршрут допустим всегда
  • Путь: массив previous[mask, last] → восстановление с конца
// DpRoutePlanner.cs — переход (mask, last) → next
long arrival = time + dist(last, next);
if (arrival > deadline[next]) return;

long done = arrival + service[next];

// отсечение: со склада уже не успеть —
// никакое продолжение не поможет
if (done + back[next] > shift) return;

int i = (mask | 1 << next) * k + next;
if (done < finish[i])
{
    finish[i] = (int)done;      // храним минимум
    previous[i] = last;
}
5
Почему DP даёт оптимум

Достаточно хранить одно число — самое раннее время

  1. Будущее зависит только от состояния: где курьер (last), что доставлено (mask) и который час
  2. Раньше — не хуже. Все ограничения — верхние границы (дедлайн, конец смены). Продолжение позднего маршрута выполнимо и для раннего — моменты прибытия лишь сдвигаются раньше
  3. Ценность определяется маской и не зависит от порядка внутри неё → поздний маршрут можно отбросить
  4. Отсечение безопасно: dist — кратчайшие, путь до склада через другие адреса не короче прямого

Проверено экспериментом

  • 1500 случайных задач: DP = полный перебор всех упорядоченных подмножеств
  • Эталон независим: свой Флойд — Уоршелл вместо Дейкстры
  • Мутация «хранить позднее время» → падают 3 теста

Граница довода: окна «не раньше» без права ждать или пробки без свойства FIFO ломают «раньше — не хуже»

На 1500 случайных задачах жадный никогда не лучше DP. Свойства жадного выбора (как каноничность монет в КТ5) у задачи нет.

Архитектурные решения 2 и 4

Чем этот проект отличается от маршрута дрона (КТ7)

Сжатие графа вместо поиска по состояниям города

Можно было, как в КТ7, искать по состояниям (перекрёсток, mask) прямо в городе.

состояний при V = 1600, k = 20
(перекрёсток, mask)V · 2^k ≈ 1,7 млрд
(last, mask)k · 2^k ≈ 21 млн

Шаг 1 убирает V из экспоненциальной части — в 80 раз меньше состояний. Между заказами курьер всегда едет кратчайшим путём: раньше — не хуже.

Время — значение, а не координата состояния

КТ7: заряд был частью ключа (станция, заряд) — «дешевле» и «больше заряда» конфликтуют, ни один путь не доминирует.

Здесь: «раньше» — единственный критерий, ценность задаётся маской. Конфликта нет → храним одно число.

Таблица в T раз меньше, чем dp[mask][last][время]: при смене 480 мин — в 480 раз.

Сложность

O(k·(V+E) log V + 2^k·k²) — и упирается всё в память

ЧастьВремяПамять
ДейкстрыO(k·(V+E) log V)O(k·V)
DP: циклы mask × last × nextO(2^k · k²)O(2^k · k)
Сборка планаO(k + путь)то же
  • Каждый новый заказ удваивает таблицу DP
  • k = 20 → ~100 МБ; k = 25 → ~4 ГБ; k = 30 → ~160 ГБ
  • Поэтому k > 20 отклоняется явной ошибкой, а не падением по памяти
  • Рекурсии в решении нет — стек от входа не растёт

Пограничные случаи и некорректные данные

Ответ есть всегда: пустой маршрут допустим

Пограничные случаи каждый — тест

  • Заказов нет → путь [Склад], возврат в 0
  • Один заказ ровно впритык / на минуту дольше смены
  • Дедлайн ровно в момент прибытия → успел
  • Смена 0 → только заказы на самом складе
  • Ни один заказ не выполним → у каждого своя причина: недостижим · нет пути обратно (одностороннее) · не успеть к дедлайну · не укладывается в смену
  • Несколько заказов по одному адресу; повторный проезд перекрёстка
  • Ровно 20 заказов — решается; 21 — явная ошибка

Некорректный ввод отклоняется явно

  • Отрицательное время проезда — ломает инвариант Дейкстры; при отрицательном цикле кратчайшего пути нет
  • Отрицательные смена, дедлайн, время передачи; ценность ≤ 0
  • Повтор номера заказа, адрес или склад вне сети, битый JSON
  • Циклы в графе — норма для города, обрабатываются без особой логики
  • Суммы времени — в long; RouteBuilder перепроверяет любой план

Границы применимости

Что сломается первым при изменении условий

ИзменениеЧто произойдёт
Заказов — сотниПервой ломается память DP (2^k · k). Дальше — кластеризация по районам + DP внутри, ветви и границы или эвристики
Город — миллионы перекрёстковРастёт только шаг 1, линейно по k. Двунаправленная Дейкстра, A*, contraction hierarchies; k + 1 запусков параллелятся тривиально
Окна «не раньше»С правом ждать — DP корректен: arrival = max(arrival, opens). Без права ждать доминирование ломается → время становится измерением, как заряд в КТ7
Пробки (время зависит от момента)Корректно, пока выполняется FIFO: выехав раньше, не приедешь позже
Вместимость сумкиПроверка по mask — размер состояния тот же
Несколько курьеровРазбиение подмножеств между курьерами — O(3^k); на практике эвристики
РаспараллеливаниеУзкое место — DP: параллелится только внутри слоя |mask| = m, упор в пропускную способность памяти

Итоги

Комбинация двух техник курса — и обоснование каждой

Графы

Список смежности и Дейкстра сжимают город из V перекрёстков до k + 1 точек

DP по подмножествам

Точный оптимум за O(2^k · k²); корректность доказана доминированием и проверена перебором

Жадный отклонён

Контрпримеры в тестах и демо: теряет до половины ценности

Главная граница метода — память при k > 20. Она осознанная: до 20 заказов DP проще и точнее любых альтернатив, а превышение отклоняется явно
