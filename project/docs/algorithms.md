# Как в проекте используются алгоритмы

Каждый алгоритм разобран по одной схеме: где он в коде, зачем нужен, как работает (с трассировкой на маленьком примере) и какая у него сложность.

## Карта: что и где

| Алгоритм / структура | Тема курса | Файл | Зачем |
|---|---|---|---|
| Список смежности | Графы | `Graph/RoadNetwork.cs` | Хранить город |
| Алгоритм Дейкстры + двоичная куча | Графы | `Graph/ShortestPaths.cs` | Кратчайшее время между адресами |
| Восстановление пути по предкам | Графы | `ShortestPathTree.PathTo` | Путь по улицам |
| DP по подмножествам (битовые маски) | Динамическое программирование | `Planning/DpRoutePlanner.cs` | **Главный алгоритм:** какие заказы везти и в каком порядке |
| Жадный «ближайший сосед» | Жадные алгоритмы | `Planning/GreedyRoutePlanner.cs` | Отклонённая альтернатива для сравнения |
| Флойд — Уоршелл | Графы, DP | `tests/.../Reference.cs` | Эталон для проверки Дейкстры |
| Полный перебор (рекурсия с возвратом) | Рекурсия | `tests/.../Reference.cs` | Эталон для проверки DP |

Решение работает в два шага:
1. **Дейкстра** сжимает город из V перекрёстков до матрицы времён между k + 1 точками (склад и адреса заказов).
2. **DP** по этой матрице выбирает оптимальный маршрут.

## 1. Структуры данных

| Структура | Где | Почему именно она |
|---|---|---|
| `List<List<Road>>` — список смежности | `RoadNetwork._adjacency` | Город разреженный (2–4 соседа у перекрёстка): память O(V + E), а не O(V²) как у матрицы |
| `PriorityQueue<int, int>` — двоичная куча | Дейкстра | Достать ближайшую вершину за O(log V) |
| `int[] distance`, `int[] previous` | Дейкстра | Доступ к вершине по номеру за O(1) |
| `Dictionary<string, int>` | `RoadNetwork._indexByName` | Перевод имени перекрёстка в номер за O(1) |
| `Dictionary<int, ShortestPathTree>` | `TravelTimes.treeByNode` | Кэш: Дейкстра не запускается дважды из одного перекрёстка |
| `HashSet<string>` | `DeliveryProblem` | Проверка повторяющихся номеров заказов за O(1) |
| **Битовая маска** `int` | DP | Множество доставленных заказов в одном числе; объединение и проверка за O(1) |
| `int[] finish`, `sbyte[] previous` | DP | Таблица DP; одномерный массив вместо двумерного, предок — 1 байт для экономии памяти |

## 2. Алгоритм Дейкстры

**Где:** [ShortestPaths.cs](../src/CourierRouting/Graph/ShortestPaths.cs), метод `Dijkstra`.

**Зачем:** найти кратчайшее время от одного перекрёстка до всех остальных. Вес дороги — минуты; веса неотрицательные (отрицательные отклоняются при вводе), поэтому Дейкстра корректна.

**Идея:** каждый раз достаём из кучи самую близкую ещё не обработанную вершину. Её расстояние уже окончательное: любой другой путь к ней идёт через вершину, которая не ближе, а веса ≥ 0. Затем пробуем улучшить соседей — это называется **релаксация**.

```csharp
distance[source] = 0;
heap.Enqueue(source, 0);

while (heap.TryDequeue(out int node, out int dist))
{
    if (dist > distance[node])
        continue;                          // устаревшая запись — пропуск

    foreach (var road in network.RoadsFrom(node))
    {
        long candidate = (long)dist + road.Minutes;
        if (candidate < distance[road.To]) // релаксация
        {
            distance[road.To] = (int)candidate;
            previous[road.To] = node;      // запомнить, откуда пришли
            heap.Enqueue(road.To, (int)candidate);
        }
    }
}
```

**Ленивое удаление.** В `PriorityQueue` нет операции «уменьшить ключ». Поэтому, если нашёлся путь короче, вершина просто кладётся в кучу ещё раз, а старая запись остаётся. При извлечении такая запись узнаётся по условию `dist > distance[node]` и пропускается.

### Трассировка

Небольшой учебный граф (двусторонние дороги, минуты):

```
Склад —6— Рынок —7— Вокзал
  |        |          |
  8        1          5
  |        |          |
  +—————— Площадь ————+
             |
             6
             |
           Парк
```

Дороги: Склад–Рынок 6, Склад–Площадь 8, Рынок–Площадь 1, Рынок–Вокзал 7, Площадь–Вокзал 5, Площадь–Парк 6. Источник — Склад.

| Шаг | Извлекли | Что сделали | Куча после шага |
|---|---|---|---|
| 0 | — | `distance[Склад] = 0` | {Склад 0} |
| 1 | Склад 0 | Рынок = 6, Площадь = 8 | {Рынок 6, Площадь 8} |
| 2 | Рынок 6 | Площадь: 6 + 1 = 7 < 8 → **улучшили**, Вокзал = 13 | {Площадь 7, Площадь 8, Вокзал 13} |
| 3 | Площадь 7 | Вокзал: 7 + 5 = 12 < 13 → улучшили, Парк = 13 | {Площадь 8, Вокзал 12, Вокзал 13, Парк 13} |
| 4 | Площадь 8 | **8 > 7 — устаревшая запись, пропуск** | {Вокзал 12, Вокзал 13, Парк 13} |
| 5 | Вокзал 12 | соседей не улучшает | {Вокзал 13, Парк 13} |
| 6 | Вокзал 13 | устаревшая, пропуск | {Парк 13} |
| 7 | Парк 13 | соседей не улучшает | {} |

Итог:

| | Склад | Рынок | Площадь | Вокзал | Парк |
|---|---|---|---|---|---|
| `distance` | 0 | 6 | 7 | 12 | 13 |
| `previous` | — | Склад | Рынок | Площадь | Площадь |

На шаге 2 видно, почему прямая дорога не всегда лучшая: до Площади напрямую 8 минут, а через Рынок — 7.

### Восстановление пути

`PathTo(Парк)` идёт по `previous` от конца к началу: Парк ← Площадь ← Рынок ← Склад. Затем список разворачивается: **Склад → Рынок → Площадь → Парк**.

**Сложность:** O((V + E) log V) по времени. Каждая дорога релаксируется один раз, в куче не больше E + 1 записей. Память — O(V).

## 3. Сжатие графа: Дейкстра из каждой ключевой точки

**Где:** [TravelTimes.cs](../src/CourierRouting/Planning/TravelTimes.cs).

**Зачем:** DP нужны только времена между складом и адресами заказов. Остальные перекрёстки города для него лишние.

**Как:** Дейкстра запускается из склада и из каждого *различного* адреса заказа, не больше k + 1 раз. Результат — матрица `Minutes(from, to)`.

**Пример — сценарий `02-greedy-trap`.** Дороги: Склад–Киоск 5, Склад–Офис-1 30, Офис-1–Офис-2 5. Точки: 0 = склад, 1 = N (Киоск), 2 = F1 (Офис-1), 3 = F2 (Офис-2).

| из \ в | Склад | N | F1 | F2 |
|---|---|---|---|---|
| **Склад** | 0 | 5 | 30 | 35 |
| **N** | 5 | 0 | 35 | 40 |
| **F1** | 30 | 35 | 0 | 5 |
| **F2** | 35 | 40 | 5 | 0 |

Например, N → F2 = 40: путь Киоск → Склад → Офис-1 → Офис-2. Дейкстра находит его сама: прямой дороги из Киоска к Офису-2 нет.

**Почему не Флойд — Уоршелл:** он считает все пары перекрёстков за O(V³). При V = 1600 это ~4·10⁹ операций, а нужны только (k + 1)² пар. k + 1 запусков Дейкстры занимают ~8 мс.

**Сложность:** O(k · (V + E) log V).

## 4. Динамическое программирование по подмножествам (главный алгоритм)

**Где:** [DpRoutePlanner.cs](../src/CourierRouting/Planning/DpRoutePlanner.cs).

**Идея** (как у алгоритма Хелда — Карпа для коммивояжёра):

- **Состояние** `(mask, last)`: `mask` — множество доставленных заказов, `last` — заказ, доставленный последним.
- **Значение** `finish[mask, last]` — самая ранняя минута окончания передачи заказа `last` при таком состоянии.
- **Переход:** из `(mask, last)` к каждому `next ∉ mask`:

```
arrival = finish[mask, last] + dist(last, next)
допустимо, если arrival ≤ deadline(next)
           и arrival + service(next) + dist(next, склад) ≤ T
finish[mask ∪ {next}, next] = min(старое значение, arrival + service(next))
```

- **База:** переход со склада, `finish[{j}, j] = dist(склад, j) + service(j)`.
- **Ответ:** состояние с максимальной ценностью маски; при равной ценности — более раннее возвращение на склад.

**Почему хватает одного числа на состояние:** все ограничения — верхние границы времени (дедлайн и конец смены). Из двух маршрутов, пришедших в одно состояние, более ранний не хуже: любое продолжение позднего ему тоже доступно. Ценность зависит только от маски, а не от порядка внутри неё.

### Битовые операции, которые используются

| Код | Что делает | Пример (k = 3) |
|---|---|---|
| `1 << k` | Количество масок, 2^k | `1 << 3` = 8 |
| `mask & (1 << i)` | Заказ i в маске? | `101 & 100` ≠ 0 → да |
| `mask \| (1 << next)` | Добавить заказ next | `001 \| 100` = `101` |
| `mask & ~(1 << last)` | Убрать заказ last | `101 & ~001` = `100` |
| `mask & (mask − 1)` | Убрать младший бит | `110 & 101` = `100` |
| `TrailingZeroCount(mask)` | Номер младшего бита | `TrailingZeroCount(100)` = 2 |

Двумерная таблица `[mask][last]` хранится в одномерном массиве: индекс = `mask * k + last`.

**Ценность маски** считается за O(1) на маску через уже посчитанную маску без младшего бита:

```csharp
valueOfMask[mask] = valueOfMask[mask & (mask - 1)] + Orders[low].Value;
```

**Порядок обхода:** маски перебираются по возрастанию. Переход только добавляет бит, поэтому новая маска всегда больше текущей: к моменту обработки состояния все пути в него уже рассмотрены.

### Трассировка на `02-greedy-trap`

Смена 75 минут, время передачи 0. Расстояния — из матрицы выше.

| Маска | last | finish | Как получено |
|---|---|---|---|
| 001 {N} | N | 5 | склад → N |
| 010 {F1} | F1 | 30 | склад → F1 |
| 100 {F2} | F2 | 35 | склад → F2 |
| 011 {N, F1} | F1 | 40 | N(5) + 35; возврат 40 + 30 = 70 ≤ 75 ✓ |
| 011 {N, F1} | N | 65 | F1(30) + 35; возврат 65 + 5 = 70 ✓ |
| 101 {N, F2} | — | — | N(5) + 40 = 45, возврат 80 > 75; F2(35) + 40 = 75, возврат 80 — оба **отсечены** |
| 110 {F1, F2} | F2 | 35 | F1(30) + 5; возврат 35 + 35 = 70 ✓ |
| 110 {F1, F2} | F1 | 40 | F2(35) + 5; возврат 40 + 30 = 70 ✓ |
| 111 {все} | — | — | любой порядок даёт возврат > 75 — отсечено |

Ценность масок: 011 → 1 + 5 = 6, 110 → 5 + 5 = **10**. Ответ — {F1, F2}, возврат в 70 минут.

**Отсечение** (`done + back[next] > shift`): если от заказа уже не успеть на склад, состояние не сохраняется. Это безопасно, потому что путь до склада через другие адреса не короче кратчайшего прямого.

**Восстановление порядка:** от лучшего состояния идём по `previous`, снимая бит последнего заказа, затем разворачиваем список.

**Сложность:** O(2^k · k²) по времени — три вложенных цикла `mask × last × next`, O(2^k · k) по памяти. Поэтому заказов не больше 20: при k = 20 таблица занимает около 100 МБ.

## 5. Жадный алгоритм «ближайший сосед»

**Где:** [GreedyRoutePlanner.cs](../src/CourierRouting/Planning/GreedyRoutePlanner.cs).

**Идея:** из текущей точки ехать к ближайшему заказу, который ещё успевает к своему дедлайну и после которого можно вернуться на склад. Повторять, пока такие заказы есть.

### Трассировка на `02-greedy-trap`

| Шаг | Где курьер, минута | Кандидаты (прибытие → возврат) | Выбор |
|---|---|---|---|
| 1 | Склад, 0 | N: 5 → 10 ✓; F1: 30 → 60 ✓; F2: 35 → 70 ✓ | **N** (ближе всех) |
| 2 | N, 5 | F1: 40 → 70 ✓; F2: 45 → 80 ✗ | **F1** |
| 3 | F1, 40 | F2: 45 → 80 ✗ | нет — возврат |

Итог: N + F1, ценность **6**, возврат в 70 минут. DP на тех же данных даёт **10**.

**Почему ошибается:** ближайший заказ (Киоск) «съедает» 10 минут на дорогу туда и обратно — ровно тех, которых потом не хватает на второй офис. Жадный выбор не учитывает будущих последствий. У задачи нет свойства, которое делало бы жадный выбор корректным: для монет в КТ5 таким свойством была каноничность системы номиналов.

**Сложность:** O(k²) после построения матрицы.

## 6. Алгоритмы в тестах

Тесты проверяют основной код **независимыми** алгоритмами: если и основной код, и эталон дают одинаковый ответ, ошибка маловероятна.

### Флойд — Уоршелл — эталон для Дейкстры

[Reference.cs](../tests/CourierRouting.Tests/Reference.cs), метод `FloydWarshall`. Это тоже DP: `d[i, j]` — кратчайший путь, проходящий только через первые `m` вершин.

```csharp
for (int m = 0; m < n; m++)          // разрешаем проходить через вершину m
for (int i = 0; i < n; i++)
for (int j = 0; j < n; j++)
    if (d[i, m] + d[m, j] < d[i, j])
        d[i, j] = d[i, m] + d[m, j];
```

Сложность O(V³). Для маленьких тестовых графов это не важно, зато код очевидно корректен. Дейкстра сверяется с ним на 300 случайных графах.

### Полный перебор — эталон для DP

Метод `BestByBruteForce` — **рекурсия с возвратом**: пробуем каждый ещё не доставленный заказ следующим, уходим в рекурсию и снимаем отметку.

```csharp
void Search(int at, long time, long value)
{
    // запомнить лучший результат, если отсюда успеваем на склад
    for (int i = 0; i < used.Length; i++)
    {
        if (used[i] || опоздали к i) continue;
        used[i] = true;
        Search(адрес i, прибытие + передача, value + ценность i);
        used[i] = false;                       // возврат
    }
}
```

- **Базовый случай:** все заказы использованы или ни один не успевает — цикл не делает рекурсивных вызовов.
- **Глубина рекурсии:** не больше k + 1. В тестах k ≤ 6, поэтому переполнения стека нет.
- **Сложность:** O(e · k!) — перебираются все упорядоченные подмножества.

DP сверяется с перебором на 1500 случайных задачах. Именно это доказывает экспериментально, что отсечение и хранение одного времени на состояние ничего не теряют.

### Проверка плана с нуля

`AssertPlanIsValid` заново проходит маршрут по расстояниям Флойда — Уоршелла. Он проверяет:
- путь состоит из существующих дорог;
- время прибытия пересчитано верно;
- дедлайны и смена соблюдены.

## 7. Сводка сложностей

| Алгоритм | Время | Память | Где |
|---|---|---|---|
| Дейкстра (один запуск) | O((V + E) log V) | O(V) | основной код |
| Матрица времён | O(k · (V + E) log V) | O(k · V) | основной код |
| DP по подмножествам | O(2^k · k²) | O(2^k · k) | основной код |
| Жадный ближайший сосед | O(k²) | O(k) | для сравнения |
| Флойд — Уоршелл | O(V³) | O(V²) | тесты |
| Полный перебор | O(e · k! · k) | O(k) стек | тесты |

**Итого для решения:** O(k · (V + E) log V + 2^k · k²). На практике шаг с Дейкстрой занимает миллисекунды, а ограничение задаёт память под DP.
